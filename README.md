# A股双通道研究看板（GitHub 零成本版）

这是一个只生成静态页面的 A 股研究看板。Cloudflare Worker 按北京时间每15分钟触发 GitHub Actions，执行主板硬过滤和 A/B/C/D/E/G 评分，再把结果发布到 GitHub Pages。

它不连接券商、不自动下单、不承诺收益。页面中的触发价、失效位和评分只用于条件化研究。

## 本地运行

```bash
python3 -m pip install -r requirements.txt
python3 scripts/build_dashboard.py
python3 -m http.server 8080 --directory site
```

浏览器打开 `http://127.0.0.1:8080`。

## GitHub 发布

1. 新建一个空 GitHub 仓库，把本目录作为仓库根目录推送。
2. 进入仓库 `Settings → Pages`，将 Source 设为 `GitHub Actions`。
3. 进入 `Actions → 更新并发布A股研究看板 → Run workflow`，先手动运行一次。
4. 运行成功后，Pages 地址会出现在工作流的 deploy 步骤与仓库 Pages 设置页。

上午从北京时间09:25开始每15分钟更新，最后一次为11:25；下午从13:05开始每15分钟更新，最后一次为15:05。Cloudflare Worker负责主触发，GitHub定时任务在每个节点后5分钟备援；若最新成功快照不足10分钟，备援任务会跳过重复构建。页面始终显示实际生成时间和下一计划时间。

交易日 09:25 前，页面展示最近一次成功的上一交易日收盘快照，并关闭全部执行通道；09:25 起恢复当日行情完整性检查，不会把旧收盘数据当成实时盘面。

每次成功更新都展示总评分前5只股票，并明确区分四层结果：总分前5、60分观察池、通道合格、当前可执行。普通隔夜只按A/B/C/G必过状态判定，热点波段只按A/D/G必过状态判定；B在14:20前不影响热点资格。页面另行展示0–100的数据可信度，该值只衡量数据齐备程度，不计入交易得分。盘面分析文字由结构化行情和评分结果按规则模板生成，不调用大模型。全市场行情覆盖率达到90%即通过完整性检查；个别分页失败会记录在数据源诊断中，覆盖率低于90%时停止生成方向判断，避免把过度残缺的行情写成当日结论。

盘中榜单历史从功能上线后开始记录。每个成功更新节点保存当时的前5名、分项得分、价格条件、数据覆盖率和排名变化；研究数据同时在`site/research/`保存全部完成评分的股票，并在后续节点回填30分钟、当日收盘、次日开盘、次日10:00、次日收盘、第3/5个交易日收盘以及5日最大有利/不利波动。标签只使用后续真实可见行情，不回写当时评分。同一计划节点只保留第一次成功结果，主任务与备援任务归入同一节点，手动运行单独标记。页面保留最近30个有记录的交易日，不补造过去缺失的数据。

## 可选 AI 盘面解读

看板支持在 GitHub Actions 中调用 OpenAI Responses API。AI 只解释程序已经生成的公开行情、评分、通道和价格条件，不参与评分，不新增候选，也不能改变买点或失效位。未配置密钥或接口调用失败时，页面继续显示原有规则模板。

1. 在 OpenAI API 平台创建 API key。
2. 进入仓库 `Settings → Secrets and variables → Actions → Secrets`，新增仓库密钥 `OPENAI_API_KEY`。
3. 可选：在同一页面的 `Variables` 新增 `OPENAI_MODEL`；未设置时使用 `gpt-5.6-luna`。
4. 进入 `Actions → 更新并发布A股研究看板 → Run workflow` 手动运行一次。

API key 只通过 GitHub Secret 注入工作流，不得写入网页、代码或公开仓库。GitHub Pages 仍是静态托管；模型 API 会按实际用量计费。

## 公开数据边界

仓库只保存静态看板与公开行情结果。不要把持仓、成本价、交易笔记、SQLite 数据库或任何密钥加入这个公开仓库。

评分规则位于 `config/scoring_candidate.json`。它是把已锁定模块权重转成机器可执行条件的试运行参数，不修改原策略；页面会明确显示参数状态。修改阈值后应重新进行前向验证。
